Конечно! Вот конспект-шпаргалка в виде кода. Для удобства чтения я оформил его как файл со стилизованными комментариями.

```javascript
/* 
 * ==============================================================================
 * GIT & GITHUB: КОНСПЕКТ-ШПАРГАЛКА
 * ==============================================================================
 */


// 2. Настройка окружения
// Настройка пользователя:
"git config --global user.name 'Name Surname'" // Установить имя автора
"git config --global user.email 'email@example.com'" // Установить email автора
"git config --global user.list" // Проверка текущих настроек

// 3. SSH-ключи (безопасное соединение)
"ssh-keygen -t ed25519 -C 'email@example.com'" // Генерирует SSH-ключ
"start ~/.ssh"                                 // Открыть папку с ключами (Windows)
"open ~/.ssh"                                  // Открыть папку с ключами (macOS)
// Скопируйте содержимое .pub файла и вставьте в Settings -> SSH and GPG keys на GitHub.

// 4. Основные команды
"git clone [url]"             // Скачивание удаленного репозитория
"git init"                    // Инициализация локального репозитория
"git status"                  // Проверка состояния репозитория
"git add [file]"              // Добавление файла в Staging area
"git add ."                   // Добавление всех изменений в Staging area
"git commit -m 'сообщение'"   // Создание коммита с описанием
"git log"                     // Просмотр истории коммитов
"git push"                    // Отправка коммитов в удаленный репозиторий
"git pull"                    // Получение обновлений из удаленного репозитория

// 5. Работа с ветками
"git branch [name]"           // Создание новой ветки
"git checkout [name]"         // Переключение на ветку
"git checkout -b [name]"      // Создание ветки и переключение на неё
"git push origin [name]"      // Отправка изменений в конкретную удаленную ветку

// 6. Работа со стешем (Stash)
"git stash"                   // «Спрятать» изменения в локальное хранилище
"git stash pop"               // «Достать» спрятанные изменения обратно

// 7. Слияние веток
"git merge [name]"            // Слияние веток (сохраняет структуру веток, может вызвать конфликт)
"git rebase [name]"           // Перебазирование (выстраивает линейную историю, чище)
// Git Rebase: если возник конфликт, разрешите его в файле, затем:
"git add ."                   // Добавить исправленные файлы
"git rebase --continue"       // Продолжить процесс ребейза

// 8. Откат изменений
"git revert [hash]"           // Отмена изменений конкретного коммита
"git revert --continue"       // Завершить процесс отката после разрешения конфликта

// 9. Дополнительно
// .gitignore: файл со списком имен папок/файлов, которые Гит должен игнорировать.
// Le Git Graph: расширение для Chrome для визуализации истории коммитов.
// Conventional Commits: соглашение о формате коммитов (напр., 'feat: ...', 'fix: ...').
// Горячие клавиши: Ctrl + L в терминале WebStorm — очистка истории сообщений.

// ==============================================================================
```

### Краткие советы по навигации:
* **Conventional Commits**: всегда старайтесь начинать коммит с типа (`feat:`, `fix:`, `docs:`, `chore:`), чтобы история была понятной.
* **Конфликты**: не бойтесь их. В IDE (WebStorm/VS Code) всегда есть визуальный интерфейс для сравнения двух версий кода.
* **Практика**: самый эффективный способ запомнить команды — создать пустой репозиторий и прогнать все действия из шпаргалки вручную.
